Do auto-generated feature labels survive held-out text?

Neuronpedia’s feature labels are written by an explainer model from a feature’s top-activating examples. They are never tested on fresh text. This study tests them: for each label, two prompts that should make the feature fire and two near-miss prompts that should not, written and predicted in advance, then scored against the real feature. A label passes only if both should-fire prompts activate clearly above both near-misses.

How the failures break down

Failure classes: silent — neither should-fire prompt fired at all. Partial — the feature fired, but weakly or on only one should-fire prompt. Near-miss beat — a near-miss prompt outscored every should-fire prompt.

What the failures look like

Most failures are not random. The label describes a broad concept; the feature turns out to be something narrower and more mechanical. One example: a Gemma feature labeled as detecting UI buttons stayed silent on ordinary prose about buttons, because it actually detects the code token btn. Across the silent features, the same shapes recur: word-form detectors, register detectors (obituary formulas, clinical-journal style, forum questions), and features bound to document structure rather than meaning.

Labels can be fixed. After the pilot, 21 failed labels were rewritten from the probe evidence and retested on fresh prompts: 15 of the 21 corrected labels passed, against 0 of 21 for the originals. That result is what Study 2 tests properly.

Study 2: can labels be made accurate?

A labeling bake-off on the same 60 Gemma layer-12 features, with the same held-out protocol for every method. Predictions are made per label, locked, and publicly committed before any scoring. Design published November 14, 2026; the run is planned for December 2026.

ABaseline — the current Neuronpedia label, fresh prompts
BFull-range examples — explainer sees stored examples across the activation range
CFeedback loop — the current label, revised against its own Study 1 failures
DNarrow-label instruction — the explainer is told to prefer narrow labels
ECareful human — a person writes the label from the same evidence (20 features)
FVerified selection — several candidate labels, the one that scores best on trigger texts ships

Pre-registered headline predictions: baseline passes at most 15% of the previously failed features; full-range examples at least 35%; the feedback loop at least 50%. If the feedback loop lands under 30%, the feedback claim is dead. Full design, prior-art scan, sample, and arm specifications are in the repository.

Method: prompts and predictions were drafted with the assistance of an AI research assistant and approved by Danny Gleason before locking. Pass rule: min(should-fire) > max(near-miss). All raw scores are in the repository.
