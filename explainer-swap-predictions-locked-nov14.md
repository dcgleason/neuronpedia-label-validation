- **Study:** Explainer swap on the Study 1 pilot sample. The same 40 Gemma-2-2B layer-12 features whose GPT-4o-mini labels Study 1 tested get ONE new label each from a different explainer (claude-sonnet-5-5), written from the same kind of evidence the original explainer saw — the feature's top-activating stored examples, with firing tokens marked. The new label is then tested under the identical Study 1 protocol. Purpose: separate "auto-labels fail" from "GPT-4o-mini labels fail."
- **Model / SAE / layer:** Gemma-2-2B (`gemma-2-2b`), Gemma Scope residual 16k, layer 12 — source `12-gemmascope-res-16k`. Identical features to `pilot-final-40.md`, in the pilot's test order.
- **Explainer input (exactly):** the feature's 10 highest-`maxValue` unique positive stored examples (de-duplicated by token sequence across the API's value bins), whole text, tokens with activation > 0 wrapped in `<< >>`. The feature's existing Neuronpedia explanation was never included in the prompt; no Study 1 result was shown to the explainer. Every feature had at least 12 unique positives, so all 40 explainers saw the full 10 examples. Exact prompts: `explainer-swap/explainer_prompts.json`.
- **Shipped-label parse rule (mechanical, applied by script):** if the reply contains a line starting "Label:", ship the last such line's text; else if the reply's final line is fully bolded, ship the bolded text; else ship the first line, verbatim. 37 of 40 replies were single-line and shipped verbatim. The rule changed the shipped text for idx 2625 (explicit "Label:" line), idx 3580 (bolded final line), and restored closing quotation marks the naive parse had stripped on idx 2580 and idx 4593. Raw generations: `explainer-swap/generations_raw.json`.
- **Protocol (identical to the pilot):** per feature, two should-fire prompts that plainly express the new label, two near-miss prompts that each change exactly one variable relative to a should-fire, and one binary prediction (PASS / FAIL) registered before any scoring.
- **Pass rule (set in advance):** a label passes if both should-fire prompts activate the feature clearly above both near-miss prompts (min(should-fire) > max(near-miss)).
- **Predictions in this file:** 22 PASS, 18 FAIL.
- **Prediction heuristics:** calibrated on Study 1's evidence. Labels naming a writable surface form (a specific token, a fixed formulaic phrase, a named register with verbatim exemplars) are predicted to pass, including several that flip pilot failures. Labels naming corpus-structure artifacts (document boundaries), diffuse registers, or positional patterns that near-misses cannot be kept clean of are predicted to fail. Where the pilot hand autopsy identified a feature's actual trigger, the reasoning says so.

## Arm-level predictions (locked)

Baseline: the original GPT-4o-mini labels passed **12/40 (30.0%)** on these features (pilot: 12 pass; failures were 17 silent, 6 partial, 5 near-miss-beat).

1. **The Sonnet labels pass at least 16 of 40 (≥ 40%)** — a clear improvement over the 12/40 baseline, though below the 22 passes the per-label calls in this draft sum to. Per-label calls have overpredicted passes in every prior arm of this study (at Llama layer 16, only 5 of 23 predicted passes actually passed), so the arm-level claim is set below the per-label sum on purpose.
2. **At least 8 of the 28 features whose GPT-4o-mini label failed will pass with the Sonnet label.** The improvement, if real, should come mainly from flips — word-form and register relabels of features the original explainer described as broad concepts — not from the already-passing labels. This draft predicts 12 flips.
3. **At least 9 of the 12 features whose GPT-4o-mini label passed will still pass.** A stronger explainer should rarely destroy a working label. The named risks are idx 483 (the Sonnet label narrowed to .NET namespaces, away from the prose mentions the feature demonstrably fires on) and idx 15337 (the Sonnet label requires repeated proper nouns, a document-scale pattern). This draft predicts 10 of 12 hold.
4. **Falsifier:** if the Sonnet labels pass **13 or fewer of 40**, the explainer-swap claim is dead — swapping in a much stronger explainer, shown the same evidence, bought nothing beyond noise, and label failure at this scale is not primarily an explainer-quality problem. A secondary reading: if the pass count lands at 16+ but the flips are almost all word-form relabels, the surviving claim is the narrower one — explainers fail mainly by writing concept labels for form features, and a stronger explainer's edge is mostly form-awareness.

## Closing notes for the lock decision

- **Nothing has been scored.** No prompt in this file has been run through the activation API. The only API calls made while drafting were the 40 Anthropic label generations and the public, keyless feature GETs used to assemble the explainer prompts.
- **What a lock would commit:** scoring is 40 features × 4 prompts = **160 activation calls**, the smallest scoring run in the study. No mechanism probes are specified for this arm; if Danny wants failure classification on the new labels' failures, that is a separate decision with its own call budget (~8–10 calls per silent failure, at pilot rates).
- **Test 25 prompt encoding:** idx 7623's new label is about line boundaries, so its two should-fire prompts contain a literal `\n` denoting an actual line break in the text to be scored. If this file is locked, the run script must convert that two-character sequence to a real newline before scoring, and the conversion must be recorded in the run output. All other prompts are single-line plain sentences.
- **Known approximation, stated in the design draft:** the swap changes two things at once relative to the original labeling — the explainer model (GPT-4o-mini → claude-sonnet-5-5) and the example presentation (Neuronpedia's GPT-4o-mini pipeline saw its own example format; this arm's explainer saw Delphi-style `<< >>` marking of tokens with activation > 0 in the top-10 stored examples). A win supports "a stronger current explainer, shown top examples in a standard marked format, writes labels that survive held-out testing more often." It does not isolate model quality from presentation format. The design draft names this plainly.
